# bilbo

## Testing

- Read `docs/testing.md` before adding or moving a test.
- `nix develop -c bazel test //...` runs every layer except tests that need the screen (`desktop`) and release.
- `--config=<layer>` runs one layer (`unit`, `contract`, `acceptance`, `integration`, `snapshot`, `e2e`, `release`); `--config=desktop` runs only screen tests; `--config=all` runs everything. Desktop tests take focus and keyboard input. A layer config also runs that layer's desktop tests: add `--test_tag_filters=<layer>,-desktop` to stay headless.
- Every run of the built binary, by hand or in a test, sets `BILBO_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME` to scratch folders and `BILBO_CONFIG` to a scratch `config.toml` that exists, empty or not: `BILBO_HOME` moves only the store, and a missing file that `BILBO_CONFIG` names is a config error.
- Every `remember` and `refresh` test also needs `HOME` set to a scratch folder, or a config that declares fixture follows: `bilbo refresh` and a `remember` that finds the again flag run the follows, and the default follows are the real `~/.claude/projects` and `~/.codex/sessions`.
- Session fixtures in `libs/entries/rust/fixtures/session/` are synthetic, written in the harness's exact field names and nesting; never copy a line of a real session into the repo.
- The `.jsonl.zst` files in `libs/entries/rust/fixtures/session/` are the plain fixtures of the same name packed with `zstd -3 --no-check` (`nix shell --inputs-from . nixpkgs#zstd`: the dev shell has none): pack a plain one again after changing it; a unit test compares each pair.
- `libs/entries/rust/tests/contract/expected.jsonl` is what `build.py` prints, written by `regenerate.py` beside it and never by hand: run it with `--build <the eval's build.py>` after changing `edges.jsonl`, and with `--corpus <unpacked corpus>` to pick `sample.jsonl` again. A line `build.py` stops on cannot go in either file: it belongs in the reader's unit tests.
- `libs/search/rust/tests/contract/expected.jsonl` is what the retrieval eval's bm25 store holds for the spans of `sample.jsonl`, and what bm25s gives for every text there and in `edges.jsonl`, of the folded text, without the words over 4,096 bytes; `libs/search/rust/src/analyze/word.rs` is Python 3.12's `\\w`; `stems.tsv.zst` is PyStemmer's stem of every word of the eval store. `libs/search/rust/src/analyze/fold.rs` is the fold by character over Python 3.12's Unicode data (a character of a non-zero combining class is dropped; a word character whose compatibility decomposition without such characters is all word characters becomes it; every other stays), a `static` written by `regenerate.py --fold` and never by hand; Hangul syllables are computed. `expected.jsonl`, `ranks.jsonl` and `stems.tsv.zst` are what bm25s gives for the folded text: after a change to the fold run `--fold`, then the lines below again. All are written by `libs/search/rust/tests/contract/regenerate.py` (its first lines say how to run it), never by hand: run it with `--store <unpacked eval store>` after changing `edges.jsonl`, with `--corpus` to pick the sample again, with `--table` for the word table, with `--stems` for `stems.tsv.zst`, the stem of every word of the eval store. `libs/search/rust/tests/contract/ranks.jsonl` (bm25s's scores and order) is written by the same script with `--ranks --questions <questions.jsonl>`, and `libs/entries/rust/tests/contract/prefaces.jsonl` by that folder's `regenerate.py --prefaces --corpus <corpus>`: never by hand.
- `recall`'s header and every stderr line it prints, and so is the `more:` line a page can end with, which each makes itself and compares, are parsed by `evals/retrieval/arms/bilbo-next/search.py` and `check.py`, which stop on a line they do not know: change them with any such line. `derive`'s two lines of standard output and the dry run's `kinds:`, `due:`, `this run:` and `entry` lines are read by `evals/retrieval/arms/bilbo-next/build.py`, which also compares a dry run's whole output with the one before it: change them with it.
- A test of `--in` by words runs an index update after it keeps its files: the label tables are filled by the index run, never by capture or by the store.
- The index folder is bilbo's by its `bilbo-index` file, written before any tantivy file: a test that builds an index folder by hand writes it.
- A test that needs a growth stamp recorded writes its files with an old modification time: `remember` records none for a file written in the same instant.
- A `read` test that needs a page to end or a record to be cut passes `--budget 256`, the smallest: the fixtures fit the default page.
- A test that holds `store.lock` to stand for another writer also holds `store.writer` in the state folder; with `store.lock` alone it stands for a reader, and `bilbo refresh` waits for it instead of setting the again flag.
- In `apps/cli/tests/derive.rs` every bilbo run is inside the test's process, and a child process holds every open file of that process until it executes, another test's `store.lock` included: a test in which a process is started, by bilbo or by the test itself, holds `alone()`, and one that runs two bilbo runs at once holds `together()` and calls `held_by_the_test()` in the thread it starts. No test sees a mark left out: a busy machine does, at a setup's `remember` that says it waits for another bilbo.
- A test that needs a format 1 store makes one with this tree and writes 1 into the four bytes of a segment's header that hold its format: no binary of this tree writes a format 1 header, and `frame` and `meta` are private to the store, so only their own unit tests call `header_of`.
- A test of a file that is gone runs `bilbo refresh` over a follow that still shows a file: a run with a target withdraws nothing, and neither does a follow whose files are all gone.
- A test that keeps a note with no file hands `sandbox::run` the bytes of standard input. An eval store holds no such note: `build.py` stops at `reindex` on the entry it did not count, `check.py` on `searched <n> entries`, and `search.py` on a note whose first line names no parent. An arm that keeps notes with `remember -` changes the three with it.
- No in-process test starts an editor: a child started inside a test's process holds that process's open files, another test's `store.lock` included. A test of `remember --edit` that needs one runs the built binary with `EDITOR` or `VISUAL` naming a script the test wrote and `TMPDIR` a scratch folder; a script that runs bilbo again is handed the binary's absolute path.
- A test file names a shared module of `apps/cli/tests/` only when it uses every item of it: split the module, never silence the lint.
- A test of the prompt builds an `Env` that says a person is at standard input and hands the answers as its bytes; what the prompt asks comes back as notices. No test has a terminal, and none holds that `main.rs` says a person only when standard input is a terminal and the stderr view is the human one.
- A test of a pass over a forgotten file makes the forgotten label with `Forgotten::label` from `Mark::of` of the bytes it says the entry held: the entries suite's `FakeEntries` computes no mark from the bytes it captures.
- A forget of an entry that holds no forgotten label yet is two calls of the store. A test that stops it between them fails the second frame the store writes (`Step::FrameWritten`), for an entry whose second call writes one: `Step::MetaSynced` is inside a new entry's first capture and never stands between the two.
- A test that a forgotten entry left `recall` asserts the count of `searched` and that no line says the index is behind or a hit was left out: `nothing matched` alone is also what a stale index gives, since `recall` checks each hit against the store.
- A test that `derive` sends nothing for a forgotten entry brings the index up first and keeps a second entry that is due: a run stopped at the scope's gate, or with nothing due, sends nothing either.
- The entries suite's `FakeEntries` keeps in `asked` every text `captures_with` was asked, the gone rule's folder paths and `forgotten:` alike: a test that means "nothing was asked about forgotten entries" asserts that `forgotten:` is absent, not that the list is empty.
- After touching `plugins/`: `claude plugin validate . && claude plugin validate plugins/bilbo` (one warning each, for the version Claude's manifests leave out on purpose; never `--strict`), and an install in a throwaway `CODEX_HOME` and a throwaway `HOME` for AGY. Codex has no validator of plugins any more.

## Rust

- After changing `Cargo.toml` or `Cargo.lock`, repin with `CARGO_BAZEL_REPIN=1 nix develop -c bazel build @crates//:all`, then run a plain `nix develop -c bazel build //apps/cli` before committing: the repin records `CARGO_BAZEL_REPIN` in `MODULE.bazel.lock`, and only a plain build reverts it. `ureq` brings `ring`, which needs a C compiler where bilbo is built.
- Lint with `nix develop -c bazel build //... --config=lint` (clippy with `-D warnings`, and rustfmt; format with `nix develop -c bazel run @rules_rust//:rustfmt`). Every Rust target sets `lint_config` to the `extract_cargo_lints` target of its Cargo package; without it `[workspace.lints]` silently does not apply.
- A new build script needs an alias of its binary, as `:script` in `libs/language/rust/BUILD.bazel`, or the lint build never checks it. Keep the line of `libs/language/rust/build.rs` that tells Cargo to watch `locales/`, a folder outside its package: no test sees it removed, and Bazel needs none.
- The dev shell has no `cargo`; run it as `nix develop -c bazel run @rules_rust//tools/upstream_wrapper:cargo -- <args> --manifest-path "$PWD/Cargo.toml"`. `cargo test --locked` and `cargo clippy --locked --all-targets -- -D warnings` must pass too: nextest, cargo-mutants and cargo-llvm-cov run through Cargo.
- Keep `BILBO_VERSION` in `tools/bazel/version.bzl` equal to `workspace.package.version` in `Cargo.toml`, and give every target that reads `CARGO_PKG_VERSION` `version = BILBO_VERSION`; nothing checks either.
- A verb's CLI side is the folder `apps/cli/src/<verb>/` (`mod.rs`: its clap `Args` with its page, and `run`; `view.rs`: its human view), registered as one `Verb` variant and one arm in `apps/cli/src/lib.rs`. `kinds()`, `listed()`, `readers()`, `rendering()`, `kind_keys()`, `notes()` (and `Notes`, what it gives), `apart()`, `lists()` and `note_ways()`, with the private helpers they call, are the only code that names a kind module; a verb gets what they give as arguments; a new kind joins the first four and, when it declares a key, the fifth, and `lists()`, with the two keys of its list, `digest.<kind>.most` and `digest.<kind>.floor`, which are the digest's settings and not the kind's and stay out of `kind_keys()`. A kind bilbo writes (`note`) has a reader and no `Kind`: it joins `readers()`, `rendering()`, `notes()`, `apart()` and `lists()`. Its logic lives in the library of its domain under `libs/`, never in a crate of all verbs; a new library lists exactly its dependents in the `visibility` of its `:rust` alias. String options use `NonEmptyStringValueParser`, so `--kind=` fails with `--kind needs a value`.
- `refresh` is the one verb with no logic and no `view.rs` of its own: its `run` is handed the pass by the root, which is `remember::follows::run`, and its output is the pass's. The pass stays in `remember/`, with what it shares with a target run.
- An entry's capture label moves to another file in one place, `moved` of `libs/entries/rust/src/remember.rs`: a file whose label holds no entry and whose `id` a kept entry holds takes that entry when `gives_way` finds that no file at the old label still gives the `id`. Four more places give an entry another capture label, all for `forget`: `write` of `forget.rs` (the forgotten label), `passed_over` of `remember.rs` (that label again, when a forgotten entry follows its `id`), and `back` there and `give_back` of `forget.rs` (a live label back). `files::at` says what is at a path, from `Files::node` and `Files::canonical`: a regular file that answers there under another canonical path is another path's file, since a volume that folds case answers for every spelling. A file its stamp skips is never asked for its `id`. A move is two writes, the meta and then the capture: a run stopped between them leaves the entry under its new label with the records it had, and the next run keeps the file. A file whose label holds one entry and whose `id` another holds is refused, when the file is read, before anything is written: a file label is freed only by a `forget` of the entry that holds it or by that entry's move.
- `Kind::withdraws_gone` is the kind's promise that a file of its that is gone is a document that is gone: `Markdown` answers yes, and `Session` keeps the default, since a harness deletes what it wrote. Only `follows::keep` asks it, after every ready follow's files are kept, so an entry that moved in the pass, also from one follow to another, is not taken for gone; and an entry whose `id` a file refused in the pass carries is left alone by every follow. A withdrawal is a capture of no bytes: nothing in the store says why a generation is empty. The entries under a follow come from `Entries::captures_with`, which matches more than the folder: `withdraw_gone` compares the paths by whole components itself.
- A note with no file is kept by `remember::keep_written`, which names no kind: `libs/entries/rust/src/note/written.rs` gives its record and its capture label, `note:<its id>`, through `notes()`. The label's form is a format: `bilbo read` prints it. The caller mints the id, since the label holds it, and `keep_written` refuses a label that holds an entry: the store finds an entry by its label before it looks at an id. It also refuses a record `bilbo_store::opaque::filter` would change, since the store's capture would keep the placeholder and say nothing. `derive` writes no notes of such an entry because the kind `note` has no instruction: an instruction for that kind would make every written note a parent. It can write the entry's summary, which needs no instruction: a note kept with `remember -` can have one, and it is no note about a note.
- `apps/cli/src/remember/edit.rs` is the one place of `apps/cli` that starts a process: the editor, which inherits the three streams and so is the one writer of the terminal that is not `main.rs`. Its command is the key `remember.editor` and its temp folder the key `paths.temp`: the module reads no variable for either. Its draft is `note.md` in a folder the run makes new under the temp folder, `.bilbo-note-<id>`: hidden, so no `markdown` follow claims a draft, and made by `console::private`, which fails on a name that is there. The store is opened only after the editor is done. The folder goes, with all it holds, when the use case answered that the note was kept or the draft held no text; in every other case it stays and the run's line names the file. An editor that could not be started and one that ran and whose end could not be had are two answers: only the first removes the folder, and no test makes a real wait fail.
- The prompt of a bare `remember` is drawn with `Message` through `Env`'s notice and reads lines of `Env`'s standard input through one buffered reader: it names no crate, and its marks are `console::theme`'s. With nobody at the terminal a bare `remember` is a usage error and never the pass.
- `remember`'s page is at the 30 lines its guard takes: a new usage form or option needs a line taken from it first. Its `Kinds:` line is built from `listed()`.
- A child of `libs` is a library named for one thing bilbo does or holds, one level deep: `settings`, `store`, `entries`, `search`, `language`, `llm`, `derive`. It holds one folder for each programming language that implements it (`rust/`), which is the crate: `Cargo.toml` and its `BUILD.bazel` sit there, since Cargo and the Rust rules each take `CARGO_MANIFEST_DIR` from their own file. Files that no programming language owns sit beside it, in a folder named for what they hold (`language/locales/`, `derive/instructions/`). `libs/<library>/BUILD.bazel` only forwards: one alias a language (`:rust`), which dependents name, and a `filegroup` of the shared files where there are any; the real target is visible to that package alone. No test holds this shape. What plugs into one of a crate's contracts is a `pub mod` of the crate that runs it, named for what it binds, a file or a folder (`entries/rust/src/<kind>/` with `entries/rust/fixtures/<kind>/`; `search/rust/src/<tool>.rs` or `search/rust/src/<tool>/`). Inside the crate, `lib.rs` declares the module and only the module and the suites that test it name the tool; outside it, only `apps/` names the module. A module becomes a crate of its own only when some build must leave it out, when it needs a toolchain the rest does not, or when it is a thing bilbo does that more than one library uses. `llm` is the third case: it was `derive`'s until the tags needed a model too, and it took its port and its providers with it. The providers stay modules of the crate that runs them. `language` is a crate for its build step: `build.rs` writes its table, and it has no layout test, since `tools/rust/layout` bans the `include!` that reads it. `libs/derive/rust/build.rs` writes the table of instructions as data, read with `include_str!`: the layout rules ban `include!`. It needs the alias `:script`, as the language crate's does. The five layout tests (`tests/layout.rs` of `libs/entries/rust`, of `libs/search/rust`, of `libs/derive/rust`, of `libs/llm/rust` and of `apps/cli`) hold the module rules above, and a failure says what to change. No guard checks two entries: a new adapter module needs its own in `ADAPTERS` of `apps/cli/tests/layout.rs`, and a new kind a row with no file in `PLACEMENT` of `libs/search/rust/tests/layout.rs`.
- `Lookup` is the read side: `bilbo_search::tantivy::Committed` implements it from segment readers and never calls `Index::reader()`, which creates `.tantivy-meta.lock`. BM25 is `bilbo_search::bm25`, over `Lookup::postings`; tantivy scores nothing. A ranking's two lists count apart: the documents of the kinds a query lists apart, and the rest, each take BM25's three numbers over their own documents, from `holding`, `Lookup::length` and the totals less them, taken off as whole numbers. A document apart moves no other document's score; with no document apart `length` is not asked and every score is the whole index's. What `recall` prints of the main list is then the same hits, order and text as without the documents apart, but for a ref and for where it ends: `Hit::shared_short` is asked of the whole store, so an entry apart that ends in a hit's short id makes that hit's header print the whole id, and a query with no candidate apart gives the main list the room apart too. `holding(Filter::Entries)` takes the whole sorted set, so how a large scope is read is the adapter's alone. `chunk::at` chunks only the passages its coordinates name: a whole entry costs a second; it says whether a chunk opens with its passage's head (`Chunk::headed`), which the index does not hold: the copy rule and the packer leave a hit's first line out only then. A change to the schema changes `FORMAT` in `position.rs`.
- A passage's first piece starts at 0, or after its head: text a chunk holds whole at its start or not at all. Only the note reader gives one, its source line; a reader of another kind that gave one would change what its index holds.
- `Lookup::near` gives terms that live documents hold, each once with its live documents; `typo::distance` (`strsim::osa_distance`: restricted Damerau-Levenshtein over characters) is the definition, held by `typo.rs`'s unit tests, and `the_terms_near_a_word_are_the_ones_the_core_distance_gives_across_segments` holds tantivy's automaton to it for terms of `a` to `z`, the only ones `Bm25` sends: a tantivy upgrade that counts those otherwise fails there. `Bm25` asks for near terms only for a term no live document of the main list holds, which is the whole index when no document is apart, and counts a near term's documents there: a term only documents apart hold is no near term.
- `recall`'s `typos:` line and the log's typos field hold index terms, `a` to `z` only: a change to `typo::Rule::edits` that lets another character through must escape both, and must hold the adapter's distance for such terms, which no test does: only terms of `a` to `z` reach `near` today.
- The bm25s ranking contract runs with `typo::Rule::OFF` and weight 0, on a table that stops the test when `near`, `pairs` or `length` is called.
- `recall::keys::Section::bm25` is the one place that builds the ranker from the `recall.*` keys: a new ranking key joins it. `digest::list` ranks with the same ranker.
- Which row a kind gets in `digest` is its reader's promise: `appends_only` gives a row that names records, anything else a row of the entry, since an edit can move every record of such a file. Nothing more is asked of a reader: a row reads its entry's newest generation whole, as `read` and `recall` do. A row is made from what a reader gives (`title`, `entry_labels`, the outline) and never from a chunk's text: `digest` loads no tokenizer and compares no row's text with the index. What a failed call of the store does goes by the call that failed and never by the error it gave, since one error of the catalog can come from any of them: a candidate's own meta, extent or records, and the entry is left out and counted `gone`, as `recall` leaves such a hit out; the lookup or the read of an entry's notes, and the row comes without its `note: ` field with nothing counted; the lookup or the read of an entry's summary, and the row comes without its `summary: ` field in the same way, each looked up apart from the other; any other call of the store, and the run ends with no list. `Reader::title` and the last line at or before a record, `last_line` of `read/outline.rs`, are the digest's alone today; the cut of an outline line, `shown` there, is also `read`'s, and a change of it changes what both print.
- The note of a passage in `digest` is found through two functions `list` is handed: from an entry's id, the capture label of the entry that holds its notes; and from one record of that entry, what it says it was written from and what a row shows of it. `libs/search` names neither `derive` nor a kind and asks nobody for a kind. An entry that belongs to one an earlier list chose is in no later list, which is why the lists are made in their order. The root hands the two: `bilbo_derive`'s label and the note's own record; a change of that label or of a note's sources changes what `digest` finds, and `a_session_with_notes_written_from_it_is_listed_once_with_its_note` is where it shows.
- A list of `digest` passes over what its values say: `libs/search` names no kind, so "the sessions' list" is said nowhere in it. What is true of an entry is judged before what is true of a chunk and counted once an entry. An entry belongs to another by the label it carries and by nothing else: a subagent's file with no label is an entry of its own, and `digest` reads no path for it. The date `old` goes by is the entry's, the one date the index holds, as `fill` gives it: a date for each chunk is a change of `FORMAT`. The instant of a run is handed to `list`, and no test of it reads a clock. Only a whole UUID names the prompt's own session: `read` takes eight characters of one, `digest` does not. The root sets a list's values for each kind in `lists()`, and the verb reads the time of day once, at its entry.
- A score in `digest` is counted over `digest::alone::Alone`, a `Lookup` of one list's kind alone, by the `Bm25` `recall` uses: each list has a view of its own, and no score of one list is compared with a score of another. A ranker that reads a new method of `Lookup` needs that method narrowed in the view, or the two verbs' scores part: `a_notes_score_is_the_same_with_other_kinds_in_the_index` fails there. The view's count of entries is 0: nothing reads it.
- The lists of `digest` share one `Held` (`digest::held`): the list of the largest kind reads the index through its first face, which never answers a posting list or a pair's list from what it kept, and the others rank over its second, which holds their share of each. The totals, a kind's documents and length and a word's near terms are asked once and serve both faces. It lives for one run, and after an error of the index nothing is asked through it: the adapter may load a newer commit then, and what was kept would be another commit's. A new method of `Lookup` gets its rule on each face; `the_second_face_answers_from_what_the_first_set_aside` holds each. The order lists are ranked in is not the order rows are chosen in.
- `digest::list` takes a `First`, which only `digest::turn` makes, after the session is marked: no code ranks for a session that was not claimed. A test that needs a list goes through `turn` with a double.
- Every run whose verb word is `digest` exits 0, `bilbo digest --help` included: `run_tuned` is the wrapper, around `dispatch`, and it turns a failure of such a run into `digest::excused` and gives every outcome of one `Exit::Always`, which keeps 0 when the result cannot be written. `bilbo help digest` is `help`'s. A new stage of `main.rs` that can fail before `run` is outside the wrapper: no test sees it.
- A prompt after a session's first opens the state folder with its `root` file, `digest.sessions`, and `digest.log` when the log is on, and nothing else: no store, no index, no tokenizer. `Store::checked` gives the state folder without the store, and a first prompt opens the store from what it gave, never from the settings again. One function of the verb opens the store and it asks for the `First`: a second place that opens it is a way round `a_later_prompt_opens_no_store_and_loads_no_tokenizer`, which sees only what the verb is handed and what it says.
- `digest`'s marks and log hold no text of a prompt and no text of an entry. `s1`, the first line of a list and the two rows are formats: an agent reads the rows. A mark is defined byte for byte in `digest/sessions.rs`: bytes after the file's last line feed mark nothing and are cut off before a mark is appended. The log's file is treated as the marks' file is, a tail cut off under the lock before a line is appended, so that each run's line stands whole; `queries.log` is `recall`'s and has no such rule. `d1` is the log's first field, which a later count reads: a line that says `listed`, `nothing` or `floor` is six fields and then five for each list that is on, so a kind added later adds fields and moves none; every other line is six fields, a `failed` one whatever it had ranked; no title, folder, line or summary of a row is logged.
- A run of `digest` says nothing while it waits for a writer and hands the store's notice to no one, so no test of the verb can tell when a run has begun to wait, and none tries with a clock. `the_store_is_opened_with_digest_wait_and_the_stores_poll` holds the wait the verb asks for, the store's own tests hold the waiting, and `a_first_prompt_that_waits_for_a_writer_tells_the_user_nothing` that it is quiet; no test holds that a run which waited then lists. The claim of a session is written over a private trait of `digest/seen.rs` for the file: `a_claim_locks_the_file_before_it_looks_and_lets_go_after_the_append` holds its order, which is what keeps two runs at once from both being first.
- A test of `digest` sets its counts, its floors, the sessions' three keys, the width and the summary's switch: each `BILBO_DIGEST_<KIND>_MOST`, each `BILBO_DIGEST_<KIND>_FLOOR` at 0, `BILBO_DIGEST_SESSION_OLD_AFTER` at `36500d`, `BILBO_DIGEST_SESSION_SUBAGENTS` and `BILBO_DIGEST_SESSION_PARTS` at `false`, and `BILBO_DIGEST_NOTE_WIDTH` and `BILBO_DIGEST_SUMMARY_ENABLED` in the test's process, the same keys in the scratch's config file for a run of the built binary, whose runner hands a child no variable. The session fixtures are dated, and none at the test's run: under the default age a suite turns red by growing old, and `1d` and `36500d` hold from a day after the fixtures' dates on, for a century. A test's hook hands a UUID that names no file the store keeps, unless the test is about the prompt's own session, or about the marks' own text, where its ids are no UUIDs on purpose: three session fixtures are named by UUIDs, and a session whose file is kept is passed over. Only `each_lists_keys_take_their_defaults_and_refuse_what_is_outside` and `the_digests_summary_switch_is_true_or_false` lean on a default.
- Every kind a reader reads has a list in `digest`: a new reader gives its kind's list `digest.<kind>.most` and `digest.<kind>.floor` in `console/settings.rs`, a line in `lists()` with the word its list's first line begins with, and its rows in the docs. Those keys are the digest's settings and not the kind's: they stay out of `kind_keys()`. `every_kind_a_reader_reads_has_a_list_with_its_word_and_its_two_keys` fails until it does. A list has a key for what it passes over only where it passes something over: the sessions' list alone, with `digest.session.old_after`, `digest.session.subagents` and `digest.session.parts`. A pass makes no capture under a half-forgotten entry (`passed_over` asks `forget::emptied` first): that capture would be its second write.
- The passes take a file for a forgotten entry's by content with `Mark::begins` and a record that ends where the mark ends; `capture::decide` asks those two and a count of records, which a forgotten label does not hold. That is enough only while a kind splits a file at its line feeds alone: a kind whose `split` of a file's first bytes depends on what follows them needs the test the two kinds have (`the_records_of_a_files_first_bytes_are_the_same_whatever_follows`).
- A pass keeps a forgotten entry's stamp by a capture of no bytes under its forgotten label, only for a file under the label that forgotten label names, and `unread_forgotten` skips the read only for that label and a stamp that is there. A stamp kept for a file found under another label would let a pass skip a different file unread.
- `forget::held` is one scan of the catalog (`captures_with`): `remember::keep` asks it at most once, and only when a claim's label holds no entry; `derive`'s plan and its replay ask it at most once each.
- `derive` asks about forgotten entries in its plan (`cover`, `summary_pre`) and again in its replay (`run.rs`), since a forget can land between the two: a new write of `derive`'s joins both. The replay also drops a notes' block made from another generation than its parent's newest, for every parent the store holds. The dry run's `entry` line gains no word for any of it: the eval's `build.py` stops on a state it does not know.
- What belongs to an entry is found in one place, `belonging` of `forget.rs`, from `Labels::belonging_to` and from the labels the root hands (`labelled()` in `apps/cli/src/lib.rs`: `derive`'s two). A new kind of entry bilbo keeps about another entry under a label of its own joins `labelled()`, or `forget` leaves it behind; no test sees one that was not added.
- `remember::Run` says whether a run is a pass or by hand, and the caller says it: a follow of one file is a pass. Only a claim that the run's target itself names, by its label or by one of its files, comes back by hand (`back`), and the tags' cap is asked of the forgotten entry before anything is written: a move stands when the cap refuses, a way back does not.
- A `forget` the store stops says the ids of its named entries in a command to run again (`forget::ended`), only once the whole list was resolved under the writer and never after a close that failed: a session's id stops naming its entry at the entry's first write, so the refs as typed are no retry.
- A way back by hand gives `derive`'s two names back before it writes the entry's own label (`forget::give_back`, called by `back`): a run stopped between leaves the entry forgotten, and the same command finishes it. In the other order an entry would be back with names no run would ever give back. A pass gives nothing back.
