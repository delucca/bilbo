# bilbo

## Testing

- Read `docs/testing.md` before adding or moving a test.
- `nix develop -c bazel test //...` runs every layer except tests that need the screen (`desktop`) and release.
- `--config=<layer>` runs one layer (`unit`, `contract`, `acceptance`, `integration`, `snapshot`, `e2e`, `release`); `--config=desktop` runs only screen tests; `--config=all` runs everything. Desktop tests take focus and keyboard input. A layer config also runs that layer's desktop tests: add `--test_tag_filters=<layer>,-desktop` to stay headless.
- Every run of the built binary, by hand or in a test, sets `BILBO_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME` to scratch folders and `BILBO_CONFIG` to a scratch `config.toml` that exists, empty or not: `BILBO_HOME` moves only the store, and a missing file that `BILBO_CONFIG` names is a config error.
- Every `remember` test also needs `HOME` set to a scratch folder, or a config that declares fixture follows: a bare run and a target run that finds the again flag run the follows, and the default follows are the real `~/.claude/projects` and `~/.codex/sessions`.
- Session fixtures in `libs/rust/kinds/session/fixtures/` are synthetic, written in the harness's exact field names and nesting; never copy a line of a real session into the repo.
- The `.jsonl.zst` files in `libs/rust/kinds/session/fixtures/` are the plain fixtures of the same name packed with `zstd -3 --no-check` (`nix shell --inputs-from . nixpkgs#zstd`: the dev shell has none): pack a plain one again after changing it; a unit test compares each pair.
- `libs/rust/kinds/session/tests/contract/expected.jsonl` is what `build.py` prints, written by `regenerate.py` beside it and never by hand: run it with `--build <the eval's build.py>` after changing `edges.jsonl`, and with `--corpus <unpacked corpus>` to pick `sample.jsonl` again. A line `build.py` stops on cannot go in either file: it belongs in the reader's unit tests.
- `libs/rust/search/tests/contract/expected.jsonl` is what the retrieval eval's bm25 store holds for the spans of `sample.jsonl`, and what bm25s gives for every text there and in `edges.jsonl`, without the words over 4,096 bytes; `libs/rust/search/src/analyze/word.rs` is Python 3.12's `\\w`; `stems.tsv.zst` is PyStemmer's stem of every word of the eval store. All are written by `libs/rust/search/tests/contract/regenerate.py` (its first lines say how to run it), never by hand: run it with `--store <unpacked eval store>` after changing `edges.jsonl`, with `--corpus` to pick the sample again, with `--table` for the word table, with `--stems` for `stems.tsv.zst`, the stem of every word of the eval store. The qwen crate's contract test reads the same `expected.jsonl`. `libs/rust/search/tests/contract/ranks.jsonl` (bm25s's scores and order) is written by the same script with `--ranks --questions <questions.jsonl>`, and `libs/rust/kinds/session/tests/contract/prefaces.jsonl` by that folder's `regenerate.py --prefaces --corpus <corpus>`: never by hand.
- The index folder is bilbo's by its `bilbo-index` file, written before any tantivy file: a test that builds an index folder by hand writes it.
- A test of what the index holds reads it through `bilbo_tantivy`. In `apps/cli`, `src/lib.rs` and `tests/reindex.rs` are the only files that name an adapter crate; under `libs/rust/search`, only each adapter's own crate and the pure crate's contract test, which counts with the real tokenizer, do. Every other test reaches the index through the binary or a fake `Index`.
- A test that needs a growth stamp recorded writes its files with an old modification time: `remember` records none for a file written in the same instant.
- A `read` test that needs a page to end or a record to be cut passes `--budget 256`, the smallest: the fixtures fit the default page.
- A test that holds `store.lock` to stand for another writer also holds `store.writer` in the state folder; with `store.lock` alone it stands for a reader, and a bare run waits for it instead of setting the again flag.

## Rust

- After changing `Cargo.toml` or `Cargo.lock`, repin with `CARGO_BAZEL_REPIN=1 nix develop -c bazel build @crates//:all`, then run a plain `nix develop -c bazel build //apps/cli` before committing: the repin records `CARGO_BAZEL_REPIN` in `MODULE.bazel.lock`, and only a plain build reverts it.
- Lint with `nix develop -c bazel build //... --config=lint` (clippy with `-D warnings`, and rustfmt; format with `nix develop -c bazel run @rules_rust//:rustfmt`). Every Rust target sets `lint_config` to the `extract_cargo_lints` target of its Cargo package; without it `[workspace.lints]` silently does not apply.
- The dev shell has no `cargo`; run it as `nix develop -c bazel run @rules_rust//tools/upstream_wrapper:cargo -- <args> --manifest-path "$PWD/Cargo.toml"`. `cargo test --locked` and `cargo clippy --locked --all-targets -- -D warnings` must pass too: nextest, cargo-mutants and cargo-llvm-cov run through Cargo.
- Keep `BILBO_VERSION` in `tools/bazel/version.bzl` equal to `workspace.package.version` in `Cargo.toml`, and give every target that reads `CARGO_PKG_VERSION` `version = BILBO_VERSION`; nothing checks either.
- A verb's CLI side is the folder `apps/cli/src/<verb>/` (`mod.rs`: its clap `Args` with its page, and `run`; `view.rs`: its human view), registered as one `Verb` variant and one arm in `apps/cli/src/lib.rs`. `kinds()`, `listed()`, `readers()`, `rendering()` and `kind_keys()`, with the private helpers they call, are the only code that names a kind crate; a verb gets what they give as arguments; a new kind joins the first four and, when it declares a key, the fifth. Its logic lives in the lib crate of its domain under `libs/rust/`, never in a crate of all verbs; a new crate lists exactly its dependents in `visibility`. String options use `NonEmptyStringValueParser`, so `--kind=` fails with `--kind needs a value`.
- `Lookup` is the read side: `bilbo_tantivy::Committed` implements it from segment readers and never calls `Index::reader()`, which creates `.tantivy-meta.lock`. BM25 is `bilbo_search::bm25`, over `Lookup::postings`; tantivy scores nothing. `chunk::at` chunks only the passages its coordinates name: a whole entry costs a second. A change to the schema changes `FORMAT` in `position.rs`.
- `libs/rust/search` is pure: it names neither tantivy, `tokenizers` nor whichlang. Each tool has one crate under it (`search/tantivy`, `search/qwen`, `search/whichlang`) that implements a port, and in `apps/cli`, `src/lib.rs` (`tokenizer()`, `index()`, `lookup()`, `detect()`) is the only source that names those crates, as it is for the kind crates. A passage over 1 MiB is cut at line ends before it is tokenized (`MAX_ENCODE_BYTES` in `chunk.rs`): one `encode` costs about 180 bytes of memory a byte.
- The Portuguese function words are the `stop-words` crate's NLTK list, named only in `libs/rust/search/src/analyze/portuguese.rs`; a unit test holds its 207 words, so a version that changes the list fails. They leave queries only: `analyze::terms` does not know them, so they change no index and `analyze::ID` stays. A whichlang version that changes an answer fails the adapter's unit test.
- The tokenizer is `Tokenizer::encode` with the file's normalizer removed: `encode_fast` and the NFC normalizer each give other tokens than the eval's, and the contract tests fail on either. `libs/rust/search/qwen/tokenizer.json.zst` is the pinned `tokenizer.json` packed with `zstd -19`; a unit test checks what it unpacks to.
- A change to the chunker, the analyzer, the stemmer's version or the tokenizer file changes what an index holds: change `analyze::ID` or `bilbo_qwen::ID` with it, so an index made before is not taken for current.
- Snapshot baselines in `apps/cli/tests/snapshots/` are plain files: after reading a failing diff, copy the rendered text over the baseline.
- A tunable is a settings key: its default, variable and range live only in its `Key` descriptor, beside the options of the crate that reads it, and `keys()` in `apps/cli/src/console/settings.rs` registers it (a kind crate's key is handed in from `kind_keys()` in `lib.rs`: `keys` and `load` take it as an argument); a clap flag for a key has no `default_value` and no `env`. The folder keys are the composition root's, in `console/settings.rs`, since more than one crate uses the folders.
- The index position's `failed` line lists the entries a run left out, and `reindex` writes each with the count 1.
- `Reader::appends_only` is the reader's promise that appending records changes no passage already rendered: `Session` answers `true`, `Markdown` `false` (a frontmatter fence closed by a later record turns earlier text into frontmatter), and the index of an entry of a kind that answers `false` is made again whole when it grows. The `Index` port has seven methods, and `position` and `extents` only read: they create, repair and empty nothing. An index grown by `remember` ranks as a rebuilt one, scores included: `a_grown_index_ranks_as_a_rebuilt_one_scores_included` holds it.
- `remember::RECORD_HELD` is an upper bound of what keeping holds for each record beside its bytes (the end `split` gives, what `capture` keeps to pack it). A change to either that passes 64 bytes a record changes it; no test holds it.
